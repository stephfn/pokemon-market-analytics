Pokémon Market Analytics¶

Integrating Pokémon Statistics, API Data, and Trading Card Market Prices Using Python, SQL, and SQLite¶

Project Overview¶

This project integrates Pokémon game statistics, PokéAPI attributes, and trading card marketplace data into a unified analytical database. Data were collected from multiple sources, cleaned and standardized using Python and pandas, stored in SQLite, and integrated using SQL joins.

The resulting dataset was used to explore relationships between Pokémon characteristics, rarity classifications, and marketplace pricing behavior. Visualizations were developed to identify factors associated with higher card values and to demonstrate the use of multi-source data integration within a relational database environment.

Project Objectives¶

  • Clean and standardize Pokémon datasets from multiple sources
  • Integrate flat-file, API, and marketplace data using SQLite
  • Perform SQL joins to create a consolidated analytical dataset
  • Explore factors associated with Pokémon card market values
  • Demonstrate end-to-end data preparation and visualization workflows

Technologies Used¶

Ethical Considerations¶

Several transformations were applied to improve the quality and usability of the dataset, including handling missing values, removing duplicates, standardizing text formatting, and removing outliers. These changes were made to enhance consistency and ensure the dataset is suitable for analysis.

Since this dataset is based on publicly available Pokémon data, there are no direct legal or regulatory concerns associated with its use. However, assumptions were made during the cleaning process, such as replacing missing values in the "Type 2" column with "None" and defining thresholds for outlier removal. These assumptions may influence how the data is interpreted.

One potential risk is that removing outliers could eliminate valid but rare observations, potentially introducing bias into the dataset. Additionally, transformations such as standardizing categorical values may alter the original representation of the data if not carefully documented.

The dataset was sourced from a widely used public dataset intended for educational and analytical purposes, and it is considered credible. No personal or sensitive information is included, and the data was acquired ethically.

To mitigate ethical concerns, all transformations were clearly documented and justified. This ensures transparency and allows others to reproduce, evaluate, or modify the data preparation process as needed.

SQL Data Integration¶

The three Pokémon datasets were integrated using SQL INNER JOIN operations on standardized Pokémon name fields. This approach preserved relationships between game statistics, API-derived attributes, and trading card marketplace information while enabling analysis across multiple independent data sources.

The resulting merged dataset combined battle statistics, Pokémon attributes, rarity classifications, card conditions, and marketplace pricing information into a unified analytical view that served as the foundation for all subsequent visualizations and exploratory analysis.

Join Strategy¶

An INNER JOIN was used to combine the three datasets based on Pokémon name fields. This ensured that only Pokémon present across all sources were included in the final analytical dataset. The join preserved relationships between game statistics, API attributes, and card marketplace information while maintaining data consistency.

SQL Query¶

In [43]:
query = """
SELECT
    w.name,
    w.pokemon_type,
    w.total,
    a.height_m,
    a.weight_kg,
    a.base_experience,
    c.rarity_class,
    c.price_usd,
    c.condition_std
FROM pokemon_website w
INNER JOIN pokemon_api a
    ON w.name = a.name
INNER JOIN pokemon_cards c
    ON w.name = c.pokemon_name;
"""

merged_df = pd.read_sql_query(query, conn)

Project Summary¶

This project integrated multiple Pokémon-related datasets into a consolidated SQLite database for exploratory analysis and visualization. The analysis combined Pokémon statistical information, PokéAPI attributes, and trading card marketplace pricing data to create a unified analytical dataset.

Several data preparation and transformation steps were performed to improve consistency and compatibility across data sources. These steps included standardizing column names, formatting Pokémon names, handling missing values, removing duplicate records, and selecting relevant analytical features. The cleaned datasets were loaded into SQLite and integrated using SQL INNER JOIN operations based on Pokémon name fields.

The resulting dataset enabled analysis of relationships between Pokémon characteristics, rarity classifications, card conditions, and marketplace pricing. Visualizations revealed that rarity and card condition appeared to have stronger associations with market value than Pokémon battle statistics alone. This project demonstrated the practical application of data cleaning, web scraping, API integration, SQL database construction, relational joins, and data visualization within a single analytical workflow.

Ethical Considerations¶

The datasets used in this project were obtained from publicly accessible sources, including PokéAPI and publicly available Pokémon card marketplace data. These sources were selected because they are widely used, structured, and appropriate for educational and analytical purposes. No personally identifiable information was collected, stored, or analyzed.

Several assumptions were made during the data preparation process. Pokémon names were used as the primary merge key across datasets, assuming that records with matching names represented the same entities. However, marketplace listings may vary because of grading differences, promotional releases, special editions, or regional variations. These factors may introduce minor inconsistencies within the merged dataset.

Potential ethical concerns include inaccurate pricing interpretations resulting from incomplete marketplace data, grading subjectivity, or seller-specific pricing behavior. Data transformation and filtering decisions may also introduce bias by emphasizing certain rarity classifications or card conditions. To mitigate these risks, original pricing values were preserved whenever possible, preprocessing decisions were documented transparently, and assumptions were clearly identified throughout the project.

This project highlights the importance of ethical data preparation practices, transparency in analytical workflows, and careful interpretation of results when integrating multiple independent data sources.
